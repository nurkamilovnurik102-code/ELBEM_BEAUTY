# EL BEM BEAUTY 2.0 — подключение Supabase (новый проект)

**Важно:** выполняйте SQL только в НОВОМ пустом проекте Supabase. Не запускайте миграции на старой базе EL BEM BEAUTY1. Демо-проект не годится для обработки реальных клиентов до проверки ролей, расписания и защиты от спама.

1. Создайте отдельный Supabase Project в Dashboard. Дождитесь состояния Active.
2. В SQL Editor последовательно выполните файлы `supabase/001_initial.sql`, `002_media_storage.sql`, `003_media_audio_realtime.sql`, `004_demo_seed.sql`, `005_booking_schedule.sql`, `006_catalog_categories.sql`, `007_client_accounts.sql`, `008_localized_catalog.sql`. **Не повторяйте файлы при ошибке вслепую; зафиксируйте точную ошибку.**
3. В Dashboard → Project Settings → API / Data API возьмите Project URL и публичный anon/publishable key. Никогда не используйте `service_role` в Vite.
4. В корне проекта скопируйте `.env.example` в `.env.local` и заполните `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`. `.env.local` не публикуйте.
5. В Supabase → Authentication → Users создайте учётную запись администратора с уникальным безопасным паролем. Выполните в SQL Editor (подставьте собственный UUID пользователя):
   `insert into public.admin_users(user_id) values ('UUID_АДМИНИСТРАТОРА') on conflict do nothing;`
6. Перезапустите `npm run dev`. Войдите через ссылку «Для администратора» в подвале.
7. В разделе **Настройки** задайте WhatsApp, Telegram как `@username` или `https://t.me/username`, адрес, график и музыку, нажмите **Сохранить настройки**. Публичный Telegram username должен принадлежать владельцу; проверьте открытие чата.
8. Пройдите тест: создайте запись как гость; на другом устройстве войдите как администратор, найдите новую запись, откройте Telegram из строки заявки, вставьте скопированный текст и отправьте его вручную. Затем подтвердите запись в админке.
9. Проверьте загрузку фото, рабочие интервалы и отсутствие пересечений. Только после этого настраивайте публикацию на Vercel с теми же публичными переменными среды.

## Telegram
Без бота и без Telegram API сайт **не отправляет сообщения автоматически**, ни по номеру, ни по ссылке. Кнопка в админке **копирует** текст записи и **открывает чат** владельца. Владелец или менеджер вручную вставляет сообщение и нажимает «Отправить». Все заявки в любом случае находятся в админке Supabase.

## Email
Уведомления о записях по email удалены. Supabase Auth может по-прежнему использовать email для входа / восстановления пароля — это отдельная функция безопасности.

## Проверки перед коммерческой эксплуатацией
Защита публичных форм от спама, корректная запись у нескольких мастеров, RLS, права Storage, загрузка с мобильного устройства, резервные копии и фактические контактные данные салона. Не включайте коммерческие заявки, пока эти проверки не пройдены.
