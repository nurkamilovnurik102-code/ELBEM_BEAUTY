# EL BEM BEAUTY 2.0 — состояние реализации

## Реализовано в исходном коде
- Публичные страницы, карточки услуг/товаров/мастеров с деталями, корзина и гостевая запись в деморежиме.
- Медиафайлы фотографий через загрузку в Supabase Storage (с настроенными RLS и bucket), просмотр фото, галерея.
- Полупрозрачные анимированные декоративные лепестки (с reduced-motion).
- Настройка адреса, графика работы и ссылки WhatsApp через админку.
- Загрузка аудиофайла в Storage, URL трека и включение музыки кликом.
- react-i18next и JSON KG/RU/EN для около 190 статических текстов интерфейса; контент БД и динамические строки требуют отдельных переводов.
- Supabase SQL: таблицы и RLS, базовые RPC для заявки и заказа, outbox для уведомлений и Realtime-публикация бронирований.

## Не подтверждено / требуется завершить до коммерческого запуска или экзамена
1. Сборка с npm и TypeScript (пакеты не удалось загрузить в этой среде) и поведенческие E2E-тесты.
2. Все страницы и данные должны быть полностью переведены; текущие словари охватывают только часть интерфейса.
3. Настоящее бронирование пока не учитывает полноценные смены мастеров и пересечение длинных услуг (SQL версии 001 демонстрационный).
4. Клиентский личный кабинет и минимум 30–40 содержательных React-компонентов не доведены до экзаменационного критерия.
5. Нужно настроить Supabase Auth, первый admin аккаунт, Storage, Edge Function secrets, расписание запуска Edge Function и реальные интеграционные тесты.
6. Админские рабочие расписания упрощены, а ручные категории/переводы контента требуют доработки.
7. Гостевой RPC требует rate limiting, антиспам и проверки согласия на обработку данных до публикации.

**Не использовать этот проект для настоящих клиентских записей, пока пункты безопасности и записи не закрыты.**

Дополнительно: миграция `005_booking_schedule.sql` реализует расчёт интервалов и конкурентное бронирование, но не проверена на запущенном PostgreSQL в этом сеансе.

- Добавлены управление категориями (SQL 006), опциональный клиентский аккаунт и серверная привязка заказов/записей к auth.uid() (SQL 007). Фактическое исполнение SQL в Supabase не проверялось.

**Актуальная схема:** нет email-уведомлений и Telegram-бота. Записи сохраняются в Supabase, в админке кнопка «Telegram» копирует заявку и открывает выбранный владельцем @username для ручной отправки. Начните с `SUPABASE_START_HERE.md`.
