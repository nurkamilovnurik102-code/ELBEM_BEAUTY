# EL BEM BEAUTY 2.0 — расширенная версия для локального тестирования

**Статус:** расширенный frontend + SQL-миграции и серверный каркас. Не готов к приёму реальных клиентских данных до тестирования Supabase, антиспама и безопасности. См. FINAL_CHECKLIST.md и SETUP_NEXT_STEPS.md.

## Запуск в VS Code

1. Установите Node.js 20+.
2. Откройте эту папку в VS Code.
3. В терминале: `npm install`.
4. `npm run dev` — откройте выданный локальный адрес.
5. `npm run build` — проверка TypeScript и сборки.

## Как посмотреть без настройки базы

Не заполняйте `.env`. Приложение запустится в **DEMO-режиме**. Товары, услуги, бронирования и редактирование контента доступны для знакомства с интерфейсом; записи сохраняются только в localStorage текущего браузера. Для демо-админки: меню → «Для администратора» → «Посмотреть демо-панель». **Это не защищённая админка** и не подходит для реального салона.

## При подключении Supabase

1. Создайте НОВЫЙ пустой проект Supabase для EL BEM 2.0; старый проект не очищайте.
2. В SQL Editor нового проекта примените `supabase/001_initial.sql`. Это первоначальная схема, **не запускайте её над действующей старой БД**.
3. Создайте файл `.env` по шаблону `.env.example`, задайте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`. Используйте только публичный ключ; **никогда не помещайте service role key в frontend**.
4. Таблицы услуг, мастеров, товаров и публичных настроек поначалу пусты. Заполняйте их через SQL seed, подготовленный и проверенный для вашей схемы, либо после безопасного назначения администратора через интерфейс. Для наполнения вручную можно использовать таблицы Supabase.
5. Для назначения первого администратора: создайте пользователя через Authentication, подтвердите email, найдите его user ID и **только через закрытый SQL Editor** выполните `insert into public.admin_users(user_id) values ('<UUID пользователя>');`. Не создавайте аккаунты с известным общим паролем.
6. Запустите сайт и войдите через меню → «Для администратора». В production работайте только с HTTPS.

## Что необходимо завершить до настоящего запуска

- Полноценный серверный календарь с расписаниями мастеров, длительностью комбинаций услуг, временными зонами, перерывами, блокировками и конфликтами интервалов. Сейчас SQL проверяет только совпадение даты/точного времени, поэтому **не готов к настоящему бронированию**.
- Защиту публичных RPC от спама: rate limiting, CAPTCHA/Turnstile, валидация номера и согласие на персональные данные.
- Безопасную загрузку файлов в Storage вместо URL-полей; управление правами и лимитами.
- Регистрацию, восстановление пароля и личный кабинет клиента по экзаменационному ТЗ. В текущей версии клиентский Auth-интерфейс не подключён к видимой навигации.
- Изменение пароля владельца через защищённый UI и проверку свежей сессии; в демо предусмотрен только сброс по email.
- Полный редактор расписания и управление связями услуг с мастерами.
- Полную локализацию KG/RU/EN; сейчас переключатель языков демонстрационный.
- Экзаменационный минимум 30–40 проверенных React-компонентов: текущая версия пока **не соответствует** этому критерию и требует рефакторинга.
- Полный комплект тестов и проверку доступности/скорости/безопасности.
- Право использования логотипа, фотографий, актуальность цен, реальный WhatsApp и наличие товаров/курсов у салона.

## Дизайн

Editorial Beauty + Modern Beauty Studio; cream `#fbf8f5`, wine `#783d55`, dark `#30272b`, soft blush `#f1e7e6`. Адаптивная сетка, hover/focus, mobile menu, плавающая связь и кнопка музыки. Изображения загружаются с Unsplash по публичным URL и служат демонстрационными примерами, а не фотографиями салона.

## Экзамен

Оригинальный PDF «Окурмен» требует рабочий API, регистрацию/вход, корзину, бронь, админку, поиск, фильтры, KG/RU/EN, день/ночь, избранное, отзывы, Vercel и минимум 30–40 компонентов. Этот архив — старт нового проекта, **не полный завершённый экзаменационный релиз**. Перед защитой довести все пункты до рабочего состояния и проверить.

## Изменения текущей версии

- Примеры подробных карточек товара/услуги/мастера; управление фотографиями и галереей.
- Единая система декоративных фоновых лепестков с поддержкой reduced-motion.
- KG/RU/EN через react-i18next; статический интерфейс частично локализован, а перевод изменяемых администратором данных требует отдельного заполнения.
- Настройки адреса, графика работы, музыки из файла, категорий, рабочих смен и пароля.
- Supabase: миграции 003–007 для Storage-аудио, очереди уведомлений, расчёта слотов, категорий и кабинета клиента.

**Порядок SQL-миграций для НОВОГО пустого Supabase:** 001 → 002 → 003 → 005 → (004 demo seed, по желанию) → 006 → 007. Это не инструкция для применения к старой действующей базе.

Для полного списка необходимой проверки, включая npm build, см. `FINAL_CHECKLIST.md`.
