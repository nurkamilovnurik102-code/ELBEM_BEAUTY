# EL BEM BEAUTY 2.0 — схема подключения Supabase после демо-проверки

**Не выполняйте этот план, пока локальные тесты и `npm run build` не пройдены.** Настраиваем по одному шагу в чате. Здесь записана последовательность, а не предложение выполнить всё сразу.

1. Создать **новый пустой** Supabase Project (старые базы не трогать).
2. Открыть SQL Editor и применить `001_initial.sql` — таблицы, RLS, серверные функции.
3. Выполнить `002_media_storage.sql` — bucket site-media; затем `003_media_audio_realtime.sql` — аудио, дополнительные форматы фото, Realtime.
4. Если нужны первоначальные примеры услуг и мастеров, выполнить `004_demo_seed.sql` **на этом этапе**, перед наполнением категорий. Для сайта реального салона лучше ввести настоящие данные позже, а не сеять примеры.
5. Применить `005_booking_schedule.sql` — server-side availability.
6. Применить `006_catalog_categories.sql` — категории каталога.
7. Применить `007_client_accounts.sql` — клиентские учётные записи / финальные RPC записи и заказа.
8. Применить `008_localized_catalog.sql` — поля переводов. **Не запускать этот набор повторно поверх действующей базы.**
9. В Authentication > Users создать *одного* владельца с его email и приватным паролем. Через закрытый SQL Editor добавить его UUID в `public.admin_users`; ключи администратора не копировать во frontend.
10. В локальном `.env.local` установить `VITE_SUPABASE_URL` и публичный `VITE_SUPABASE_ANON_KEY`. Никогда не помещать `service_role` в Vite или Vercel.
11. Проверить как гость: каталог, свободные интервалы, запись и заказ. Проверить как администратор с другого браузера/устройства: защищённую запись, подтверждение/отмену, фотографию и музыку в Storage, настройки WhatsApp/Telegram/карты, смену пароля.
12. После аудита RLS, антиспама публичных RPC и конкурирующих броней опубликовать на Vercel с теми же **публичными** переменными среды. Протестировать домен и mobile.

## Где что хранится

- Без базы (demo): услуги, записи, настройки — в localStorage **этого браузера**, фотографии — в IndexedDB **этого браузера**. Это не резервная копия и не синхронизация устройств. Демоданные автоматически не переносятся.
- После подключения: услуги, записи, заказы, текст и настройки — PostgreSQL; логин/пароль — Supabase Auth; изображения и музыка — Supabase Storage. Публичные фотографии — в `site-media`; гостевые записи создаются только через серверный RPC; админские действия — с RLS.
- Telegram: хранится только настраиваемая ссылка; без бота сообщения вручную отправляют клиент/администратор.
- Ссылка на карту: значение `addressMapUrl` хранится внутри JSON `site_content.data` и **не требует новой SQL-колонки**.

## Ограничения

Сборка npm и действующая база пока не проверены в этой среде. Не разрешено считать проект безопасным для реальных клиентов до проверки Supabase и защиты от спама. Сборку и авторизацию надо проверить до передачи владельцу.
